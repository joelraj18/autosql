Part 1 · every file rides this line

From upload to the junction

Stop 1

Profile every column

A column's type is how it is stored; its role is how a model should use it. Rules are checked in this order, first match wins.

  • IFonly one distinct value → constant (dropped)
  • IFstored as a date, or text where ≥ 90% parses as dates → date (becomes year / month / weekday)
  • IFwhole numbers, unique in > 95% of rows, and counting 1, 2, 3… or named like id / key → ID (dropped)
  • IFother numbers → numeric
  • IFtext averaging > 30 characters with spaces → free text (set aside)
  • IFtext unique in > 95% of rows → ID; > 50 distinct values → many categories; otherwise → category

Booking_ID → ID (100% unique text). arrival_year/month/date detected as one date split in three.

All 11 columns numeric; nothing to drop.

4 numeric columns.

Stop 2

Choose what to predict

You decide how the target is chosen. Most tables are collected to predict one thing; some have no answer column at all.

  • 🤖 AUTOa column named like status, target, label, churn, cancel, fraud… with 2–15 values (or numeric with any number of values) → predict it; else the last column if it is a category with 2–15 values → predict it; else → clustering (the engine says why)
  • 🎯 PICKyou choose any column → predict it (the trace notes when the engine would have chosen differently)
  • 🔍 NONE→ clustering; a column named like an outcome is still left out of the groups

Let the engine decide → booking_status (its name says "status", 2 values).

Let the engine decide → target (named like an outcome, numeric with 214 values → regression).

Let the engine decide → no outcome column found → clustering.

Stop 3

Quality gates

Some files can't give a trustworthy result. The app stops and explains instead of guessing.

  • STOP IFfewer than 30 rows
  • STOP IFfewer than 2 columns
  • STOP IFmore than 60% of all cells are empty
  • STOP IFthe target is free text, a date, a single value, or an ID (a different value in every row)
  • STOP IFafter clean-up no inputs are left (clustering needs ≥ 2)

36,275 rows, 0% empty → passes.

442 rows → passes.

150 rows → passes.

Stop 4

Clean up

Messy inputs either crash models or quietly make them worse.

  • IFID, constant, free text, or > 40% empty → drop the column
  • IFyear + month + day columns share a prefix → build the real date, add weekday; impossible dates (29 Feb 2018) left blank
  • IFexact duplicate rows ≤ 5% → drop (looks like double entry)
  • IFduplicates > 5%, or rows identical apart from the ID → keep, but also score the model on "unseen" test rows
  • IFno target and a column is named like an outcome → leave it out of clustering
  • IFa number is ±infinity (usually a division by zero) → treat it as missing
  • ALWAYSgaps → median (numbers) or a "missing" category (text)

Drop Booking_ID; add arrival_weekday (37 impossible dates); keep 10,275 look-alike rows (28%).

Nothing to clean.

1 exact duplicate (0.7%) → dropped.

Stop 5 · the junction

Pick the task

The type of answer you want decides the whole rest of the route.

  • IFno target → clustering
  • IFtarget is a number with more than 15 distinct values → regression
  • ELSEclassification: binary if 2 classes, multiclass if more (classes seen only once are dropped first)
  • IFfewer than 200 rows → small-data warning: one test row moves the score a lot

Part 3 · regression and classification rejoin here

Find the best model, honestly

The golden rule on this line: every choice (model, settings, threshold, resampling) is made with cross-validation on training rows only. The test set is used once, at the end.

Stop 6

Compare 5–7 models

3-fold cross-validation on up to 10,000 training rows. The highest average wins; the rule-of-thumb pick is only a first guess.

  • ALWAYSlinear, decision tree, random forest (bagging), AdaBoost and gradient boosting (boosting)
  • IFinstalled → also XGBoost and LightGBM
  • IFthe simple linear model is within 0.01 of the winner → suggest it (easier to explain)

Macro F1: LightGBM 0.862 ≈ random forest 0.858 ≈ XGBoost 0.857 > … > logistic 0.761.

Linear regression wins (0.48): the relationship really is close to a straight line.

Stop 7 · only if imbalanced

Handle the rare class

Compare class weights with random oversampling, random undersampling and SMOTE. Resampling happens inside each training fold only.

  • IFsmallest ÷ largest class < 0.25 and imbalanced-learn installed → run this stop; keep the best method

Stop 8

Tune the winner

RandomizedSearchCV tries up to 8 setting combinations (depth, learning rate, α/λ regularisation…) with 3-fold CV.

  • IFthe winner has no settings to tune (linear regression) → skip
  • IFno combination beats the defaults → keep the defaults

8 combinations tried; none beat LightGBM's defaults (0.859 vs 0.862), so the defaults stay.

Linear regression → nothing to tune.

Stop 9

Train on all training rows, sit the final exam

Score on train and test, plus the extras that apply.

  • GAPtrain − test ≤ 0.05 generalises · ≤ 0.15 mild overfitting · > 0.15 overfitting
  • IFlook-alike rows → also score test rows with no twin in training
  • IFbinary → ROC curve and AUC; regression → MAE and predicted-vs-actual
  • IFtest set under 100 rows → warn that each row is worth several points
  • IFtest score ≥ 0.99 → leakage warning: real data is rarely that easy, so check that no column gives away the answer

Test macro F1 0.88 (baseline 0.40), ROC-AUC 0.96; 0.84 on test rows with no twin in training.

Test R² 0.45, average error 42.8.

Stop 10 · binary only

Tune the decision threshold

Default: say "yes" above 50% probability. Lower catches more (recall) with more false alarms (precision).

  • PICKthe threshold with the best F1, from out-of-fold training predictions

Threshold 0.44 lifts recall 0.81 → 0.82, but F1 dips slightly, so the note says to keep 0.50.

A 3-question decision tree in real units, then permutation importance (how much the score drops when a column is shuffled).

  • IFthe 3-question tree is no better than the baseline → say so: the pattern needs many columns
  • IFit matches or beats the full model → recommend the simple rules

Part 5 · not automated yet, here is the code

Going further by hand

These course techniques aren't run automatically. Paste them into the downloaded notebook after the "Train" cell; they reuse its variables (X_train, y_train, preprocessor, …).

Early stopping and the validation-loss curve

Boosting adds trees until the validation error stops improving, instead of a fixed number.

from xgboost import XGBClassifier
from sklearn.model_selection import train_test_split
Xa, Xv, ya, yv = train_test_split(X_train, y_train, test_size=0.2,
                                  stratify=y_train, random_state=42)
prep = preprocessor.fit(Xa)
codes = {c: i for i, c in enumerate(sorted(y_train.unique()))}
xgb = XGBClassifier(n_estimators=2000, learning_rate=0.05,
                    early_stopping_rounds=50, eval_metric="logloss")
xgb.fit(prep.transform(Xa), ya.map(codes),
        eval_set=[(prep.transform(Xv), yv.map(codes))], verbose=False)
loss = xgb.evals_result()["validation_0"]["logloss"]
plt.plot(loss); plt.axvline(xgb.best_iteration, ls="--")
plt.xlabel("trees"); plt.ylabel("validation log-loss"); plt.show()
print("best number of trees:", xgb.best_iteration)

SMOTE for mixed numbers and categories

Plain SMOTE invents in-between values such as "0.4 of a category". SMOTENC keeps categories whole.

from imblearn.over_sampling import SMOTENC
from imblearn.pipeline import Pipeline as ImbPipeline
from sklearn.impute import SimpleImputer
from sklearn.compose import ColumnTransformer
fill = ColumnTransformer([("n", SimpleImputer(strategy="median"), num_features),
                          ("c", "passthrough", cat_features)])
cat_idx = list(range(len(num_features), len(num_features) + len(cat_features)))
pipe_nc = ImbPipeline([("fill", fill),
                       ("smote", SMOTENC(categorical_features=cat_idx, random_state=42)),
                       ("prep", ColumnTransformer([
                           ("n", StandardScaler(), list(range(len(num_features)))),
                           ("c", OneHotEncoder(handle_unknown="ignore"), cat_idx)])),
                       ("model", clone(tuned_model))])
pipe_nc.fit(X_train, y_train)

Threshold from business costs

Instead of best F1, choose the threshold that costs least. Example: a missed cancellation costs €100, a false alarm €10.

cost_miss, cost_false_alarm = 100, 10
proba = pipe.predict_proba(X_test)[:, list(pipe.classes_).index(positive)]
is_pos = (y_test == positive).to_numpy()
cuts = np.linspace(0.05, 0.95, 91)
cost = [cost_miss * ((proba < t) & is_pos).sum()
        + cost_false_alarm * ((proba >= t) & ~is_pos).sum() for t in cuts]
best = cuts[int(np.argmin(cost))]
plt.plot(cuts, cost); plt.axvline(best, ls="--"); plt.show()
print(f"cheapest threshold: {best:.2f}")
